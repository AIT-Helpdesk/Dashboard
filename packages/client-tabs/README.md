# @dashboard/client-tabs

Dashboard page: "CLIENT" in the sidebar -- a tabbed bundle of the dashboard's per-client lookup and report pages. Generated by Tab Page Builder. The actual tab-strip mechanism (drag-to-reorder, admin-only add/remove/reorder, the shared permanent-tabs/removed-default-tabs/tab-order settings) lives in `@dashboard/shell`'s `tab-page-client.js`/`tab-page-server.js`, reused by every tabbed page on this dashboard -- see those files for the full implementation, not repeated here.

- `client.js` - calls `createTabbedPageMount()` with this page's own `id`/`label`/`apiBase` and its eight default tabs.
- `server.js` - re-exports `createTabPageRouter(__dirname)`.

## Default tabs

- **Check Client** (`check-client`) -- a combined, read-only lookup of Orders, Subscriptions, M365 tenancy, Contract Services, and Datto RMM devices/alerts for one client.
- **Client Activity** (`client-activity`) -- ticket volume and logged hours for the last 12 months, a currently-open ticket snapshot, and tickets created in that window, for one client.
- **Client Financials** (`client-financials`) -- a 12-month invoiced-amounts summary (Labour / Recurring Services / Charges) plus the invoice list, for one client.
- **Client Info** (`client-info-tabs`) -- see "Orphaned default tab" below; there is currently no package behind this id, so this tab can't actually be opened.
- **Client Summary** (`client-summary`) -- a single-client "at a glance" page combining company details, a financial snapshot, active contracts, open ticket activity, and a 1-month Security Alerts summary.
- **Contract Services** (`contract-services`) -- search a service/bundle by name and pick a month, see every matching active contract line, grouped by company.
- **Contract Services** (`contract-services-update-contracts`) -- the same underlying report mounted a second time under a different id; see "Contract Services appears twice" below.
- **M365 Environment** (`m365-environment`) -- a client's Microsoft 365 tenant snapshot (domains, licenses, privileged roles) as recorded in IT Glue.

See each page's own README for the full behaviour of each tab -- this page doesn't change any of them, it just mounts their existing `client.js` module in a tab.

## Orphaned default tab: Client Info

`client-info-tabs` is listed in this page's own `default-tabs.json`/`defaultTabs`, but no `packages/client-info-tabs` directory currently exists anywhere on this dashboard (confirmed against the whole `packages/` tree). It's currently hidden via this page's own `removed-default-tabs.json`, which is consistent with there being nothing left behind it to show -- restoring it (drag it back in from the sidebar, or right-click undo) would hit `tab-page-client.js`'s own dynamic-import-failure path rather than mounting a real page.

## Contract Services appears twice

`contract-services-update-contracts` has no code of its own -- it's a second sidebar entry for `packages/contract-services`, one of three such pairs on this dashboard (see `packages/ingram-orders-update-contracts/README.md` for the full explanation of why this pattern exists and exactly what is/isn't shared between the two entries). Both tabs here show the same underlying report; they're independent tab/module instances with their own separate module-scope state, not two views of one shared one.

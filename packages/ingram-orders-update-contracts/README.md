# @dashboard/ingram-orders-update-contracts

No code of its own -- a second sidebar entry for `packages/ingram-orders`, by request ("also a copy of these... don't remove them from where they are, just create a copy"). `dashboardPage.client`/`.server` in `package.json` point straight at `../ingram-orders/client.js`/`server.js` via a relative path -- `packages/shell/server.js`'s own `path.join(page.root, page.client)` (both for `sendFile()`-ing the client module and for `require()`-ing the server router) resolves that correctly to the real files, confirmed by reading that code rather than assumed.

What this actually means in practice:
- **Server-side is genuinely shared, not duplicated.** `require()` resolves both this package's `server.js` path and the original's to the exact same absolute file path, so Node's module cache hands back the *same* Router instance and the *same* in-memory caches (`reportCacheByKey`/`detailCache` etc.) -- mounted at a second, independent `/api/ingram-orders-update-contracts` base path alongside the original's `/api/ingram-orders`. Harmless (same underlying Ingram data either way) and actually a small win (one shared cache, not two).
- **Client-side is a genuinely separate instance.** The browser fetches `/pages/ingram-orders-update-contracts/client.js` as its own distinct URL -- byte-identical content, but a *different* ES module instance from `/pages/ingram-orders/client.js`, with its own separate module-scope state (`lastData`/`lastSince`/etc.). The two sidebar entries behave like two independent copies of the same tool (each remembers its own last search), not a single live-synced view.

No other page in `packages/shell/nav-layout.json`'s tree can list the same page id twice and have both survive -- confirmed in `packages/shell/public/app.js`'s `reconcileTree()`, which deduplicates by id on every load, keeping only the first occurrence it finds and silently dropping any later one. A real second package with its own id is the only way within this system's actual design to get a page listed in two menu locations at once. If this pattern is needed again, this package (and its two siblings, `contract-services-update-contracts`/`ingram-subscriptions-update-contracts`) is the template.
